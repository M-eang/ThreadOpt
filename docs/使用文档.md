# ThreadOpt 使用文档

安卓应用线程 CPU 亲和性优化程序（基于 AppOpt 的 Rust 重构版，独立维护）。

通过自定义规则，把指定应用/线程绑定到指定 CPU 核心上：游戏渲染线程绑大核、后台服务绑小核，在流畅与省电之间自由调配。

---

## 一、安装

### 环境要求

- 已 Root，且安装了 **KernelSU**（含 reSukisu 等衍生版）或 **Magisk v20.4+**
- ARM64 设备（Android 11+，8 核及以上体验最佳）

### 安装步骤

1. 下载模块包：`ThreadOpt-v2.2.1-module.zip`（GitHub Releases 页面，或仓库 `modules_update/` 目录）
2. KernelSU：打开 **KernelSU Manager** → 模块 → 右上角「从本地安装」→ 选择 zip
   Magisk：打开 **Magisk** → 模块 → 「从本地安装」→ 选择 zip
3. 安装完成提示后**重启手机**
4. 重启后模块自动生效，无需任何操作

### 验证安装成功

```bash
# 终端执行（需要 root 权限的终端，如 MT Manager / Termux + su）
su -c "ps -A | grep ThreadOpt"
# 应看到 ThreadOpt 进程在运行
```

## 二、快速开始

配置文件位置：**`/data/adb/modules/ThreadOpt/applist.conf`**

```bash
# 用文本编辑器打开（MT Manager、Re 管理器等），修改后保存
# 无需重启！配置热加载，保存后 1~2 秒内自动生效
```

### 最简单的一条规则

把微信所有线程绑定到"小核+中核"（能效优先，省电）：

```

```

把游戏渲染线程绑到大核（性能优先）：

```
com.tencent.tmgp.sgame{UnityMain}=hp-core
```

## 三、档位切换（游戏档 / 省电档自动切换）

ThreadOpt 支持两个档位，自动跟随前台应用切换：

| 档位 | 配置 | 定位 |
|------|------|------|
| 省电档（默认） | `applist.conf` | 日常使用：后台收紧、前台宽松，低功耗且流畅 |
| 游戏档 | `game.conf` | 打游戏：游戏线程全上性能核，帧率优先 |

**工作原理**：每 2~4 秒检测一次前台应用，前台是 `game.conf` 中的游戏包名 → 自动切游戏档；回桌面/其他应用 → 自动切回省电档。判定依据系统 `oom_score_adj`（前台活动窗口 adj≈0，后台进程 ≥200）。

**`game.conf` 中的包名既是游戏规则，也是前台检测名单**——想自动切档的游戏，把它写进 `game.conf` 即可（模块自带常用游戏模板，按需增删）。

**手动锁定档位（兜底）**：在配置目录（`/data/adb/modules/ThreadOpt/`）建 `mode` 文件，内容三选一：

```
auto     # 跟随前台自动切换（默认，删除 mode 文件或留空也视为 auto）
game     # 强制游戏档（不管前台是什么）
power    # 强制省电档
```

> 注意：只有**当前生效档位**的配置修改后"保存即生效"；另一个档位的配置在下次切到该档时生效。查看当前档位：`su -c "ps -A | grep ThreadOpt"` 的输出，或看绑核日志（见"验证与排障"）。

## 四、规则语法

### 基本格式

```
包名 = CPU范围
```

- `包名`：应用包名（如 `com.tencent.mm`），或进程名（如 `surfaceflinger`）
- `CPU范围`：见下文"CPU 范围"

### 注释

`#` 或 `//` 开头的行是注释，不会生效：

```
# 这是注释
// 这也是注释
com.tencent.mm=4-5   # 行尾不能写注释
```

### 三种规则形态

**1. 包级规则** —— 匹配该包的所有线程：

```
com.example.app=4-5
```

**2. 块语法** —— 给特定线程单独设规则：

```
com.example.game {
    main_thread=0-3      # main_thread 绑 0-3
    render_*=4-5         # render_ 开头的线程绑 4-5
    worker_?=6           # worker_ + 1个字符 的线程绑 6
}
```

**3. 紧凑单行** —— 块语法的简写：

```
com.example.app{heavy_thread}=6-7
```

**4. 混合** —— 包级规则 + 块内线程规则同时生效：

```
com.example.app=0-3 {
    bg_thread=4-5        # 包内其余线程绑 0-3，bg_thread 绑 4-5
}
```

### 线程匹配与合并

- 一个包可以有多条规则，匹配到的线程 **CPU 集合取并集**
- 未匹配到线程规则的线程：如果有包级规则 → 用包级规则；如果该包只有线程规则 → 绑到全部核心（兜底，避免被系统限制）
- 完全没匹配的包 → 不干预

## 五、线程名通配符

| 符号 | 含义 | 示例 |
|------|------|------|
| `*` | 匹配任意字符序列（含空） | `render_*` 匹配 `render_thread`、`render_worker` |
| `?` | 匹配恰好一个字符 | `worker_?` 匹配 `worker_1`、`worker_A`，不匹配 `worker_12` |
| `[范围]` | 匹配集合中任一字符 | `thread_[0-9]` 匹配 `thread_0`~`thread_9`，不匹配 `thread_a` |

组合使用：

```
com.example.game {
    Render* = hp-core      # 渲染线程组
    AudioTrack_? = p-core  # 音频线程组
    Thread[0-9] = e-core   # 编号线程组
}
```

> 线程名来自内核 `comm`（最长 15 字符），可在手机上用 `ps -T -p <pid>` 查看真实线程名。

## 六、CPU 范围

```
0            # 单个 CPU
0-3          # 连续范围
0-3,5,7-8    # 逗号分隔（自动合并排序）
```

### 语义核心名（推荐！自动适配机型）

| 语义名 | 含义 |
|--------|------|
| `e-core` | 能效小核（最低频率簇） |
| `p-core` | 性能中核（中间频率簇） |
| `hp-core` | 高性能大核（最高频率簇） |
| `all-core` | 所有核心 |

按 `cpuinfo_max_freq` 自动分组，**换手机不用改规则**：

```
# 8 核 3 簇机型（如天玑 9200+：e=0-3, p=4-6, hp=7）：
com.example.game=e-core,p-core {    # 等价于 0-6
    UnityMain=hp-core               # 等价于 7
}
```

语义名与数字范围可混用：

```
com.example.app=hp-core,1,3-5
```

## 七、命令行参数（高级）

模块以默认参数运行，一般无需修改：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-c <file>` | 省电档配置文件路径 | `./applist.conf` |
| `-g <file>` | 游戏档配置文件路径（不存在则档位切换禁用） | `./game.conf` |
| `-s <秒>` | 检查间隔（≥1） | `2` |
| `-b <name>` | 自定义 `/dev/cpuset` 目录名（防检测） | `ThreadOpt` |
| `-v` | 版本信息 | — |

手动测试（需 root）：

```bash
su -c "/data/adb/modules/ThreadOpt/ThreadOpt -v"
```

## 八、验证与排障

### 查看规则是否生效

```bash
# 已创建哪些 cpuset（每个目录 = 一组规则目标）
su -c "ls /dev/cpuset/ThreadOpt/"

# 某个 cpuset 里绑了哪些线程
su -c "cat /dev/cpuset/ThreadOpt/7/tasks"

# 检查某进程当前归属
su -c "cat /proc/<pid>/cpuset"
```

### 常见问题

| 问题 | 原因与解决 |
|------|-----------|
| 规则没生效 | 检查是否带 `#` 注释掉了；确认包名/线程名拼写；`/dev/cpuset/ThreadOpt/` 里有没有对应目录 |
| 改配置后无反应 | 保存文件（inotify 监听写入事件），确认路径是 `/data/adb/modules/ThreadOpt/applist.conf`；若当前是游戏档，省电档配置在切回省电档时才生效 |
| 游戏没自动切档 | 确认游戏包名在 `game.conf` 里（包名即检测名单）；`mode` 文件是否被设成了 `power` |
| 想强制某个档位 | 配置目录建 `mode` 文件，内容 `game` / `power` / `auto` |
| 找不到进程 | 包未运行；线程名超过 15 字符被截断，用 `ps -T` 看真实名字 |
| 部分规则加载 | 程序日志会打印"解析完成，共加载 N 条规则"，N 少了说明有语法错误行被跳过 |

### 查看运行日志

```bash
# 前台手动运行观察输出（Ctrl+C 退出）
su -c "/data/adb/modules/ThreadOpt/ThreadOpt -v"
```

## 九、更新与卸载

- **更新**：KernelSU Manager / Magisk → 模块页 → 检查更新（配置了 updateJson 的版本）或重新安装新 zip
- **卸载**：模块页 → 卸载 → 重启；`/dev/cpuset/ThreadOpt` 目录会保留，重启后自动清理

## 十、示例规则集

```ini
# 系统图形组件 → 小核+中核（系统流畅且省电）
surfaceflinger=e-core,p-core

# 微信 → 小核+中核，渲染线程大核
com.tencent.mm=e-core,p-core {
    RenderThread=hp-core
}

# 王者荣耀 → 全部核心，Unity 渲染线程大核
com.tencent.tmgp.sgame=all-core {
    UnityMain=hp-core
}

# 抖音 → 渲染线程中核+大核
com.ss.android.ugc.aweme {
    RenderThread=p-core,hp-core
}

# 桌面 → 全核（操作跟手）
com.miui.home=all-core
```

## 十一、安全说明

- 本项目基于 [AppOpt](https://gitee.com/sutoliu/AppOpt)（GPLv3）重构，源码与文档见 [GitHub](https://github.com/M-eang/ThreadOpt)
- 规则只做 CPU 亲和性调整，不修改应用本体，卸载模块即完全恢复
- 极端规则（如把所有进程绑死单个核心）可能导致卡顿，修改后先观察再长期使用
